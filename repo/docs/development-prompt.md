# 跨平台单词本开发 Prompt

使用方式：将本文完整交给具有文件编辑、终端和构建能力的编程模型。正文包含从零复现产品所需的功能与验收要求，不依赖原聊天记录。默认名称和包名可自行替换；若在已有项目中继续开发，应保留已有应用身份、数据格式和签名。

---

你是一名负责交付的跨平台软件工程师。请实现下述单词本产品，交付可运行代码、构建脚本、测试、说明文档及环境允许生成的运行产物。不要只给设计方案、静态页面或模拟数据演示。

## 1. 产品目标与范围

开发一款供个人在电脑和手机上背英语单词的软件，默认中文名“拾词”，英文名“Wordbook”。名称是项目命名，不代表改造了同名开源软件；不保证名称或商标独有。

从零新建时，默认 Android 包名为 `com.example.wordbook`，初始版本 `0.1.0`、构建号 `1`；这些是可配置默认值，不必照搬原产品的历史版本号。已有项目沿用原包名和签名，并递增原版本。

功能目标对齐以下完整规格。支持 Windows 绿色免安装版、Android APK、Web，并提供微信小程序及 iOS 的工程与平台适配。优先交付 Windows、Android 和 Web 的完整主流程；其余平台的签名、授权、编译与真机验证状态必须分别说明。

一期不做账号、云数据库、跨设备自动同步、付费服务、在线词典查询或 OCR。单词、音标、释义、例句来自用户文件或手工编辑，不擅自调用网络服务补全。

可以使用开源框架和库，但单词本业务按本规格实现。明确说明自写业务逻辑与第三方组件的边界，保留必要许可证，不声称所有底层代码均为原创。

## 2. 工作方式

1. 先检查工作目录、已有源码、构建环境、Git 状态和项目约定。已有项目不得重置用户改动或覆盖个人数据。
2. 简要说明实现顺序后直接实施。常规实现选择自行决定，不因细枝末节反复询问；缺少签名、平台账号或授权时，继续完成不依赖它们的工作。
3. 从可运行的最小闭环逐步实现完整功能，每阶段执行相应验证。遇到失败先定位和修复，不把未通过的测试写成通过。
4. UI 必须连接实际数据与文件能力。不要将浏览器临时变量、占位按钮、固定延时模拟发音或静态卡片当成成品。
5. 若无法生成某平台安装包，明确缺少什么、已完成什么、如何继续；不能将 App 资源目录称为 APK/IPA，也不能将模拟器检查称为真机验收。

## 3. 技术路线

默认沿用以下架构，可因明确的兼容性问题调整，但应优先复用业务逻辑：

- Vue 3 + uni-app + Vite：页面、组件与跨端适配。
- 无 UI 依赖的 JavaScript 模块：单词本模型、解析规则、队列、备份比较等，便于 Node 测试。
- SheetJS：Excel/CSV；PDF.js：文本 PDF。若使用官方本地 `.tgz` 依赖，在 package.json 中声明，由包管理器自动安装，不要求用户手动解压。
- Electron：Windows 便携程序，开启上下文隔离、关闭渲染进程 Node 集成，使用受限 preload/IPC。
- Android 独立 Java WebView 壳：复用 Web 构建，提供原生 TextToSpeech 与系统文件导出桥接；使用 Gradle 构建 APK，不强制依赖 HBuilderX。
- iOS / uni-app 原生运行时：提供文件与语音适配，真实签名打包需要对应环境和证书。
- 微信小程序：共享可支持的页面与业务逻辑，单独适配文件和语音能力。

使用 pnpm 管理依赖，提交 package.json、锁文件及必要 vendor 包。选择兼容版本并写入文档；不要把旧示例版本描述为当前最新版本。PDF.js 主库和 Worker 必须严格同版本；对旧 Android WebView 可使用配套 legacy 构建，不混用 modern 主库与 legacy Worker。

- Windows 程序放在 desktop 子目录，不把 EXE/DLL 散落在 dist 根目录。

- 保留 vendor、Gradle Wrapper 与许可证；不要因“不是业务源码”误删构建所需文件。
- PDF Worker 等生成副本可清理，但构建脚本必须先自动生成，当前运行产物中必须包含它。
- 更新 Windows 程序只更新 desktop，不覆盖 input、data、backups、previews。共享程序时不要附带个人资料。
- 删除、移动目录前核对解析后的绝对路径。清理仅针对确认可再生或过期的文件，不能把运行库或个人资料当成冗余文件。

## 5. 数据模型与稳定身份

至少实现如下语义，可在保持兼容性的前提下扩展：

```js
State = {
  version: 1,                // 数据格式版本，与应用版本独立
  books: [Book],
  settings: {
    theme: 'light', fontSize: 18,
    autoPronounce: false, repeat: 1, interval: 3, rate: 0.85
  }
}
Book = {
  id, name, sourceKey, updatedAt,
  entries: [{ id, word, phonetic, meaning, example, status: 'new' }],
  study: {
    mode: 'alpha',
    alpha: { current: 'normalized-word', completed: false },
    random: { queue: ['normalized-word'], current: 'normalized-word', completed: false }
  }
}
```

study 的两种会话可在首次使用后才创建。`status` 仅有 `new` 和 `hidden`。

- 单词匹配键使用 NFKC 规范化、去首尾空白和英文大小写归一化；不要修改用户显示的原始拼写。
- 保存进度按稳定单词键，而非只依赖可能在导入/恢复时重建的词条 ID。
- 源身份默认 `file:` 加包含扩展名的小写文件名。同名不同目录视为同一源；文件改名视为新来源，并在界面说明。
- 复制本有独立 id、sourceKey 和队列副本，不受原始文件再次导入影响。
- 多个本保存在同一应用存储中，不要求每本一个磁盘文件夹；隐藏词就是各本 entries 内的状态。
- 校验备份的版本、结构、身份、字段类型、重复词和状态。损坏数据不能静默丢弃或被空数据覆盖。

## 6. 文件导入与预览

1. 一个源文件生成一本独立单词本；Excel 的所有工作表合并进同一本。
2. 支持 xlsx、xls、CSV、文本 PDF，以及备份 JSON / 解析预览 JSON；默认导入大小上限 30 MB，超出时明确提示。
3. 识别中英文表头与不同列顺序：单词、音标、释义/中文释义、例句；支持词性独立列并合理并入释义。无表头时按四列约定读取。
4. PDF 按页面文本坐标重建行；明显双栏应先读完一栏再读另一栏，避免把同一高度的左右两词拼成一条。复杂断行与词组不保证自动校对正确。
5. 无文本层的扫描 PDF 提示先 OCR，不能假装解析成功。解析失败、超时应退出忙碌状态并释放 PDF 文档/Worker。
6. 导入前提供预览，可编辑四个字段、逐行保留/剔除、全选/全不选，显示来源位置和问题。预览按约 50 条分页，避免大量词条一次渲染。
7. 空词、重复、缺释义、疑似页码/页眉等标记问题，问题行默认不选。确认时仍拒绝选中的空单词和规范化后的重复词；零有效词不得创建或覆盖单词本。
8. 同一源再次导入，明确提示覆盖。确认后保留单词本 id、自定义名称、仍存在词条的隐藏状态及可保留进度；释义等内容更新，未导入的旧词移除。
9. Windows 提供“扫描 dist/input → 选择文件 → 解析并预览”；其他平台使用本机文件选择。手机不能扫描电脑目录。
10. 所有源文件解析在设备内完成，不上传文件或偷偷调用在线词典。

## 7. 单词本与词条管理

- 列表展示名称、总词数、生词数及隐藏进度，支持搜索、重命名、复制、删除、导出单本。
- 删除前确认，并按后述规则保留恢复点。复制必须是独立数据，不共享可变数组。
- 提供词条管理：按单词/释义搜索、全部/生词/隐藏词筛选，结果按约 25 条分页。
- 支持新增、编辑、删除；拒绝空词和规范化后的重复词。
- 编辑拼写保留状态，并更新两种队列内对应键；删除当前词或删空一本不能导致越界。
- 搜索结果可跳转到卡片；若词已隐藏，明确执行恢复后再跳转。
- 手工编辑可能被下一次同源覆盖替换，说明如何通过备份或独立副本保留修改。
- 用户词条内容按纯文本显示，不将导入内容作为 HTML 或脚本执行。

## 8. 卡片与续背规则

1. 正面显示单词，翻面显示音标、释义、例句；缺字段提供提示。每张卡片有手动发音按钮。
2. 两种排序：字母顺序与 Fisher–Yates 完全乱序。只对 new 生词建队列，不用不可靠的随机 sort 比较器。
3. 每本单独保存两种排序的队列/当前位置，以及上次使用的排序方式；切换本、退出、重开程序后准确续背。
4. 乱序队列生成后持久化，重新进入或切换页面不得重新洗牌。
5. “重新开始本轮”确认后只重置当前排序，乱序重新洗牌，另一种排序进度保留。
6. 隐藏当前词后继续到下一个可背词；独立隐藏词列表可逐个或全部恢复。
7. 新增或恢复的词追加到已有乱序队列末尾，保留原有顺序；字母排序按规则插入。覆盖导入后重整队列，保留仍有效当前位置，移除当前词时选合理后继。
8. 提供一次“撤销隐藏”，恢复该词并返回原卡片位置；离开页面后可清除即时撤销入口，但仍能从隐藏列表恢复。
9. 队尾显示“本轮已完成”并停止，不自动循环。完成标记持久化；可后退查看或明确重开。跳转到后半段后到队尾，不应声称用户已逐一学习所有词。
10. 电脑左右方向键切词、空格翻面；输入框、弹窗编辑和组合快捷键不误触。手机水平滑动切词，纵向滚动不触发切词。
11. 全隐藏、空单词本、最后一词被删除/隐藏时均提供正常空态和恢复入口。

## 9. 发音、自动朗读与连播

- Windows/Web 调用系统或浏览器 SpeechSynthesis；Android APK 调用原生 TextToSpeech。不是实时上网搜索单词，也不依赖远程音频 URL。
- 离线朗读取决于是否安装离线英文语音包。Android 优先使用不需网络的英文语音，缺失时提示，不悄悄切换在线服务；Web 不能保证所有浏览器声音都离线。
- 提供自动发音、开始/暂停连播、每词 1–3 次、间隔 1–15 秒、语速 0.5–1.5 倍；默认自动发音关闭、重复 1 次、间隔 3 秒、语速 0.85。
- 等待实际朗读完成事件后再开始间隔和切词，不能用估算单词长度或固定延时当成发音结束。
- 用请求标识/取消机制处理快速切卡、取消、旧回调和多次播放，过期回调不能驱动新一轮。
- 切页、打开词条管理、应用进入后台、发生发音错误、到达队尾时停止；回到前台不自行续播。超时给出可理解提示。
- 微信使用获授权的语音插件，说明它需要网络；无 AppID/授权时保留明确配置入口和说明，不伪造插件可用。
- 微信及尚未验证完成事件的旧 uni-app 原生分支可先保留手动朗读，明确能力差异，不让连播假装正常。

## 10. 持久化与手动备份

- 使用设备本地存储。Windows 开发/发布版按项目相对路径使用 dist/data，移动整套目录后仍能定位；Web 按浏览器来源隔离，手机保存在各自沙箱。
- 写入成功后才提交内存状态；保存失败提示用户备份，不能悄悄丢失进度。读取损坏数据时阻止后续破坏性写入，提供原始数据导出和恢复入口。
- 支持导出单本或全部。全部导出为一个 JSON，带 schema 版本、exportedAt、所有独立单词本、来源、词条、隐藏状态、两种进度与乱序队列。
- 三本导出一个 JSON，空设备恢复后仍是三本，不合并成一个大本。旧版缺少 study 的备份可恢复并从头开始。
- JSON 支持文件选择与粘贴。恢复前逐本比较词条新增/移除、内容、隐藏状态、进度及日期；不要按显示名称误判同一本。
- 已有本默认“保留本机”。“合并新增词”只补入本机没有的词，保留本机内容、状态和进度；“使用备份覆盖”才完整使用该本备份。新本默认导入，可逐本跳过；未涉及的本保留。
- 恢复不覆盖当前设备主题、字号、播放和界面语言偏好。语言单独保存，不因恢复而切换。
- 快照只代表导出时刻，不自动同步、不自动判断电脑或手机哪边更新。换设备前提示导出最新备份。
- Windows/Android 等待系统保存完成，取消/失败不记作成功导出；Web 只能记录发起下载时间，应诚实表述。
- 未导出过全部数据或距上次导出超过 7 天时显示备份提醒。

## 11. 本地恢复点

- 有旧数据时首次保存、每隔 24 小时的首次修改，以及编辑、删除、覆盖导入、备份恢复前保存旧快照。
- 最多保留最近两个；空间不足可降为一个。进度变化不在每次切词时无限产生快照。
- 提供查看、比较恢复、单独导出和清理恢复点。
- 破坏性修改前无法保存恢复点时，阻止该次修改并提示先导出备份；普通进度保存不因恢复点失败而中断，但应提示备份。
- 恢复点与应用数据同在一个设备，不包含在常规跨设备 JSON 导出中，不能当作卸载或清除数据后的保险。

## 12. 中英界面、主题与版本

- 默认中文，在“基础设置 → 界面语言”切换中文 / English，立即生效并持久化，重启保留。
- 翻译主页面、导入预览、卡片操作、词条管理、备份比较、帮助、错误、确认弹窗及无障碍标签；不要只翻译几个导航按钮。
- 使用统一消息表与参数插值，不用运行时扫描 DOM 替换中文的方式实现翻译。
- 不翻译或修改单词本名称、单词、释义、例句、源文件内容。语言控件保留“中文”“English”自称，方便切回。
- Windows 原生菜单、窗口标题、关于弹窗随语言同步；中文菜单只写“帮助”，英文只写“Help”，不显示“帮助（Help）”。系统文件窗口语言由操作系统决定。
- 支持浅色/深色主题、卡片字号 14–28 px；保证桌面和手机英文长文案不横向溢出。
- 关于页显示当前应用版本与构建号；右上角帮助和设置中的关于入口都能到达。移除角落常驻版本号和不必要的重复版本文案。
- 界面、Windows 包元信息、Android versionName/versionCode 统一管理并校验一致，不散落硬编码。升级递增 Android versionCode。
- 帮助页解释导入、续背、隐藏词、离线语音条件和备份迁移。无需联网也能查看。
- 页面样式应覆盖子组件弹窗，特别检查 uni-app 页面自动作用域导致弹窗背景/排版失效的问题。

## 13. 平台交付与安全边界

### Windows

- 生成 dist/desktop/Wordbook.exe 与完整 Electron 运行目录，双击无需安装。不要声称只复制一个 EXE 即可运行。
- 使用受限文件 IPC，检查文件名、类型、大小和路径，不允许渲染层任意读取文件系统。
- 打包完整替换网页资源，清理旧哈希文件，不累积历史 bundle；排除 Electron 默认示例应用，保留运行库与许可证。

### Android

- 交付真正可安装 APK，所有 Web 资源与 PDF Worker 内置；通过稳定本地来源加载，不能只是打开远程网站。
- 原生桥接使用请求 ID 匹配成功、取消、错误和朗读完成。用系统文档选择器导入，SAF 选择导出位置并实际写入文件，不申请不必要的全盘访问权限。
- 提供 Gradle 本地构建及可选 GitHub Actions 路径；文档列明需要的 Node、JDK、SDK 和构建工具。
- 包名稳定、签名持久保存并跨构建恢复。不能仅依赖会过期的 CI 缓存保存唯一签名；私钥放 Secrets/安全存储，绝不放公共仓库或公开构建产物。
- 验证证书一致及覆盖安装保留数据。若签名不同，停止并说明，不以卸载有个人数据的应用作为默认修复办法。
- 输出 APK、SHA256SUMS.txt、build-info.json，记录版本、构建号、提交、构建来源、哈希及证书摘要；不包含私钥。

### Web / 微信 / iOS

- Web 提供静态服务器和离线缓存。首次通过 HTTPS 或 localhost 加载缓存后才能离线使用；不能要求用户双击 HTML，也不能假装从未加载过即可离线打开。
- 微信提供构建文件、真实 AppID/插件配置说明；支持聊天文件 Excel/CSV/JSON 与粘贴恢复。不能直接处理 PDF 时，引导电脑转换预览或备份 JSON。
- iOS 提供可构建工程、文件导入导出与语音代码；缺少签名环境时明确尚未生成 IPA。文件共享和语音需要真实安装验证。
- 不把第三方网络图片、字体或远程 Worker 作为离线核心界面的必需资源。

## 14. 验收要求

测试使用独立目录/存储和自己生成的 Excel/PDF/JSON 夹具，不能依赖用户的真实文件名，更不能清空 dist/data 或其他个人资料。

至少覆盖以下场景，不能只检查文件存在或页面能打开：

1. 三个源文件生成三个本；Excel 多工作表仍为一本；中英文乱序表头、脏数据默认排除和编辑后确认可用。
2. 同源覆盖保留改名、隐藏状态和有效进度；未选中的旧词移除；复制本不受影响。
3. 两套排序分别续背，乱序重启不重洗；三本互不串进度；状态不依赖旧词条 ID。
4. 隐藏/恢复/删除当前词、追加新词、重开当前排序、全隐藏/空本均正确；队尾不循环；撤销隐藏回原卡片。
5. 修改拼写保留状态并更新队列；空词、大小写/全角等价重复词被拒绝。
6. 实际发音完成才切换；取消旧请求、切页、后台和错误不会让旧回调推动队列。区分逻辑模拟与真实听音测试。
7. 三本导出一个 JSON，另一套空存储恢复仍三本；包含隐藏词和两套进度；旧版备份可读。
8. 恢复默认不覆盖，保留/只合并新增/显式覆盖各自正确；本机偏好保持；坏 JSON 和损坏结构不丢数据。
9. 存储不足时普通保存、破坏性修改、恢复点降级按规则处理；损坏本地数据可导出原始内容。
10. 中英切换覆盖主要弹窗、错误及帮助；重启保留语言，书库内容和进度不变，Windows 菜单同步。
11. 桌面键盘、手机滑动、明暗主题、字号和中英窄屏布局实际可用；输入/弹窗不误触快捷键。
12. Windows 在 file 协议下本地 PDF Worker 真正解析文件；Web、微信、App 构建分别完成并标注验证层次。
13. Android 模拟器实际安装、启动、关停续背、覆盖升级、导出 JSON 到用户可见位置、重新选择导入、解析真实文本 PDF，以及语言重启记忆。

Android 多场景测试如需重新载入旧调试包，可在一次性模拟器中明确允许夹具降级或重置环境；这与产品覆盖升级不同，不能在用户设备上自动卸载应用。

将测试命令、通过/失败结果、截图和未验收项记录到验证文档。不要为凑测试数量编写无意义断言，也不要提前填“已通过”。
